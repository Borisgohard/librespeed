# 魔改实现说明

原版 LibreSpeed 的核心能力是测量浏览器到测速服务器之间的网络质量。用户打开网页后，浏览器负责下载随机数据、上传测试数据并多次发起空请求来计算延迟。这个模式适合判断本地网络到某台 VPS 的线路，但不能直接回答“两台 VPS 之间线路怎么样”。

本次魔改保留了原版能力，同时新增了服务器间双向测速。固定端 VPS 会主动测量测试端 VPS，测试端 VPS 也会反向测量固定端 VPS。这样得到的结果就是两台服务器之间的实际 HTTP 链路表现。

新增功能集中在 `new/project/vps-agent` 和 `new/project/vps.html`。代理接口负责在服务器端执行测速，页面负责让用户从浏览器触发双向测试。原版首页、经典界面、现代界面、稳定性测试页面和 PHP 后端测速接口都继续保留。

下载测速时，源 VPS 请求目标 VPS 的 `backend/garbage.php`，目标端返回指定大小的随机数据，源端根据收到的字节数和耗时计算吞吐。上传测速时，源 VPS 临时生成测试数据并 POST 到目标 VPS 的 `backend/empty.php`，目标端不保存数据，源端根据发送字节数和耗时计算吞吐。延迟和抖动测试时，源 VPS 多次请求目标 VPS 的 `backend/empty.php`，根据每次 HTTP 往返耗时计算平均延迟、最大延迟、最小延迟、抖动和失败率。

所有代理接口都要求访问令牌。固定端调用测试端时也必须带同一个令牌。这样可以避免公网用户随意触发两台服务器之间的大流量测试。令牌默认保存在本地 `new/.vps_token`，不会写入公开页面，也不应该上传到 GitHub。

代理版本 `1.2.0` 增加了严格结果判定和单任务锁。下载、上传命令不仅要正常退出，目标 HTTP 状态也必须是成功状态；三个指标或两个方向中任意一项失败，顶层结果都会标记为 `error`。同一节点已有测速时，新请求返回 HTTP `409`，避免并发任务把带宽和 CPU 占满。

令牌只允许放在 `X-LibreSpeed-Token` 请求头，不再接受 URL 参数。错误令牌返回 `401`。当前演示服务仍使用 HTTP，因此令牌在传输层没有加密；正式使用应加 HTTPS 或至少通过防火墙限制来源。

固定端适合长期运行。测试端可以经常更换。更换测试端时，不需要重装固定端，只需要把魔改服务部署到新测试端，并保持令牌一致。部署完成后，本地交互式脚本或固定端的 `/vps.html` 页面就能重新发起双向测试。

测速结果中的 `lossPct` 是 HTTP 延迟采样请求失败比例，不是 ICMP 数据包层面的严格丢包率。用户界面和新文档把它称为“HTTP 请求失败率”，避免把两个概念混为一谈。
