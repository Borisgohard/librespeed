# 交互脚本实现思路

## 目标

交互脚本的目标是让用户只在本地电脑操作，不需要手工登录两台 VPS，也不需要记住长命令。脚本必须同时支持“服务已经部署，只拿结果”和“需要自动部署一端或两端”两类场景。

固定端通常长期不变，测试端经常更换。因此所有输入和代码路径都围绕角色设计，而不是假设两台机器永远共用一套 SSH 配置。

## 角色和入口

`interactive_vps_pair.ps1` 是 Windows 入口，只负责控制台编码、寻找 Python 和传递退出码。业务逻辑全部在 `interactive_vps_pair.py`。

交互脚本复用 `deploy_vps_pair.py` 的打包和 SSH 部署函数，不复制第二套远端部署逻辑。只做 HTTP 操作时，部署模块不会加载 Paramiko；真正部署时才检查 `new/requirements-deploy.txt` 中的依赖。

## 动作驱动的输入

脚本先让用户选择动作，再决定后续需要哪些输入。这样只健康检查时不会询问测速流量，只测速时不会询问 SSH，部署一端时也不会要求填写另一端无关的密码。

动作集合分为四类：需要固定端部署、需要测试端部署、需要健康检查、需要测速。一个动作可以同时属于多个集合。代码根据集合判断流程，避免在多个位置重复写编号条件。

## 固定端和测试端独立配置

两端配置都由 `NodeConfig` 表示，包含角色、主机、Web 端口、SSH 端口和 SSH 用户。固定端和测试端可以使用完全不同的 SSH 端口、用户名和密码。

更换测试端时，本地请求动态携带新地址。固定端不需要保存一张测试端清单，也不需要因为地址改变而重启。

## 令牌设计

代理令牌默认保存在 `new/.vps_token`。脚本可以复用或让用户输入；只有同时部署两端时才允许随机生成。单端部署和纯 HTTP 操作如果找不到现有令牌，会要求用户输入，不能静默生成一个与另一端不匹配的新令牌。保存后会尝试把权限限制为当前用户可读。

报告不记录令牌明文，只记录 SHA-256 的前 16 个十六进制字符作为指纹。指纹用于判断某次运行是否复用了同一令牌，不能用来恢复原令牌。

## HTTP 请求和结果判定

健康检查分别访问原版首页、双 VPS 页面和令牌健康接口。每个请求记录状态码、本地耗时、响应大小、尝试次数、JSON 和短文本预览。

只读 GET 请求仅在连接失败或 502、503、504 时最多尝试三次。POST 测速只发一次；超时不意味着远端没有启动，自动重试可能重复耗流量。401 认证失败和 409 任务忙不会重试。双向总超时根据下载、上传、延迟采样和两个方向计算。

成功不能只看 `pair.php` 的顶层字段。脚本还检查正反两个方向，并确认每个方向的下载、上传、延迟状态都是 `ok`。只要一项失败，摘要和退出码都表示失败，但仍保存完整报告。

## 时钟偏差

健康接口返回节点 UTC 时间。脚本在收到响应后和本地 UTC 比较，误差绝对值超过 30 秒时给出警告。时钟警告不直接把 Web 健康状态判为失败，因为它不影响服务可达性和本机持续时间计算，但必须写入报告，防止用户误读跨节点时间线。

## 报告策略

JSON 保存程序排错需要的完整结构。Markdown 用自然语言回答：本次做了什么、有没有 SSH、两端是什么、每个页面是否可用、服务器时钟是否正常、两个方向指标是多少、失败原因在哪里、如何复跑。

正常和异常路径都会尝试保存报告。全部通过退出 `0`；取消退出 `1`；未捕获执行异常退出 `2`；检查完成但业务结果失败退出 `3`。这让人工运行、计划任务和外部监控都能判断结果。

## 高可用配合

交互脚本本身不负责长期驻留。它调用部署模块的候选镜像、健康检查和回滚流程；调用代理的单任务锁避免重复点击造成并发压测；本地重试抵抗短暂网络波动。

这种设计把一次性控制面放在本地，把持续服务放在 Docker 容器中。用户关闭本地脚本后，两台 VPS 的网页和代理仍继续运行。

## 2026-09-06：降低误操作成本的改进

本轮不是增加新的测速模式，而是把经常重复的输入和高风险确认分开。地址、端口、协议、用户名可选择保存到本地私密配置，下次作为可修改默认值；没有历史配置时必须明确输入自己的机器地址。损坏配置会报错，不偷偷换回作者的服务器。

输入令牌只改变内存。用户最终确认、至少一个节点部署或认证健康检查成功后才写令牌；测速成功也可以确认保存。写入采用同目录临时文件替换，变更时保留一代旧令牌。取消和输入结束不会消耗默认同意，也不会覆盖原令牌。

每轮明确给出有效流量预算：默认 64/32 MiB 双向共 192 MiB，各节点约发送和接收 96 MiB。报告增加实际字节、耗时、完整成功样本、极值及短样本提示。没有执行、没有启动和执行失败分别叙述，避免新手把“有报告”理解为“所有步骤都成功”。

SSH 身份采用系统已知主机加项目独立记录。陌生主机显示 SHA256 指纹并必须输入 yes；已有密钥不符直接拒绝。本轮没有增加后台驻留、自动重试测速或自动调整系统参数，这些都会超出本地交互测速的边界。

## 2026-09-06：干净下载与公开隐私

新手不应先判断 Python 包装入口和解释器环境是否一致。统一入口只做版本校验与环境选择，不复制测速逻辑；原六个动作、每步暂停、SSH 指纹确认和最终默认取消全部沿用。缺依赖的提示放在选择部署之后、输入地址和密码之前，因此环境准备不会接触服务器，也不必暂存用户密码后重启流程。

环境安装仍需显式同意，默认取消。新建的 `.venv` 只属于当前项目；已有环境优先复用，残缺环境先停下提示，不自动删除。日常 HTTP 测速走标准库路径，不为一个不需要 SSH 的动作强制下载依赖。

公开记录与私密原始记录分层：匿名版保留技术证据和失败边界，原始版保留本地完整上下文。仅用忽略规则无法清理旧历史，因此发布前还要验证提交元数据和 GitHub 可访问对象。新的隐私回归测试使用保留地址段，不把待隐藏的真实 IP 再写进测试用例。
