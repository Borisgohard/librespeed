## 正确性和安全测试

错误令牌在两端都返回 HTTP `401`。跨域预检返回 `204`。故意把目标指向不存在的 LibreSpeed 根路径时，下载、上传和延迟全部返回 `error`，证明错误页面不会被算成成功测速。并发启动两个测试时，第一个正常完成，第二个返回 `409`，证明单节点任务锁生效。

令牌只接受 `X-LibreSpeed-Token` 请求头，不再接受 URL 参数。SSH 密码不写文件，`new/.vps_token` 和真实报告不进入 Git。

## 部署与恢复能力

两端最终镜像基于固定的官方镜像摘要构建。部署脚本在旧容器继续运行时构建候选镜像，切换前保存回滚镜像，候选容器通过令牌健康检查后才宣布成功。两端实际成功升级路径已经验证。

候选失败后恢复旧镜像的代码路径已经实现，但本轮没有故意破坏正在使用的服务做故障注入，因此不能把该分支描述成已经在线演练通过。

## 已知环境警告

固定端系统时钟约落后本地 `253` 秒，测试端约落后 `188` 秒。两端都没有启用 NTP。本地报告已把它们标记为时钟警告。

该偏差不会直接改变由单节点持续时间计算的下载、上传和 HTTP 往返耗时，但会让原始 JSON 中两个节点的绝对时间不能严格排序。由于系统时间跳变可能影响服务器其他业务，本轮没有擅自修改。

## 更换测试端

固定端可以长期不动。以后只需运行本地交互向导，选择动作 `4`，输入新测试端 IP、Web 端口及其自己的 SSH 信息，并复用现有 `new/.vps_token`。脚本只部署新测试端，然后自动检查两端、执行双向测速并生成报告。

## 结果使用边界

本项目给出的失败率是 HTTP 延迟采样请求失败比例，不是 ICMP 协议层的严格丢包率。测速数值也只代表当次 HTTP 测试，建议至少使用 64/32 MB、在同一时间段重复三次后比较，不要用 1 MB 小样本判断长期线路容量。
