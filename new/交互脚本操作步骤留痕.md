# 交互脚本操作步骤留痕

## 为什么增加本地交互入口

最初的 `deploy_vps_pair.py` 适合自动化，但参数较多。为了让用户在不手工 SSH 登录服务器的情况下完成日常操作，增加了 `interactive_vps_pair.py` 和 Windows 包装入口 `interactive_vps_pair.ps1`。

交互脚本不是把终端输出机械复制进文档。它会整理执行动作、两端配置、每个 HTTP 检查、时钟偏差、双向指标、失败原因和原始数据位置，再生成中文自然语言报告。

## 当前交互顺序

第一步选择动作。动作一共六种，覆盖只健康检查、检查加测速、两端部署、只部署测试端、只部署固定端和只测速。

第二步输入固定端 IP 或域名、Web 端口和 HTTP/HTTPS 协议。第三步对测试端填写相同类别的信息。首次运行没有机器地址默认值；保存过配置时，向导逐项提供上次值并允许修改。

只有选择部署动作时，第四步才会出现 SSH 信息。固定端和测试端分别询问端口和用户名，不再强迫两端共用相同配置。如果只做健康检查或测速，脚本会明确提示不需要 SSH，并直接跳过端口、用户和密码。

第五步处理代理令牌。检测到 `new/.vps_token` 时可以直接复用。只有动作 `3` 同时部署两端时，才允许按 Enter 生成高强度随机令牌；单端部署或纯 HTTP 操作必须输入已经存在于服务器的令牌，避免两端认证不一致。令牌文件会尽力限制为当前用户可读，并被 Git 忽略。

第六步只在测速动作中询问下载大小、上传大小、延迟采样次数和单项超时。只健康检查时不再要求填写无关的测速参数。

第七步只在部署动作中询问密码。两端都部署时，脚本会先询问固定端密码，再询问两端密码是否相同；不同则单独输入测试端密码。密码不写报告。

执行前脚本打印动作、两端地址、必要的 SSH 目标、测速参数、令牌文件和不可逆推出令牌的短指纹，还会说明本轮流量。随后询问是否保存无密码节点配置，最后确认必须输入 y；直接回车为取消。首次 SSH 还需核对指纹并明确输入 yes。

执行完成后，脚本保存 Markdown 和 JSON 两份报告。全部所选检查通过时退出码为 `0`；用户取消为 `1`；执行异常为 `2`；流程完成但健康或测速失败为 `3`。

## Windows PowerShell 兼容处理

完备性复验时，Windows PowerShell 5.1 无法正确解析无 BOM 的中文 UTF-8 包装脚本，表现为中文乱码和字符串终止符错误。

最终包装脚本改为 UTF-8 BOM 和 CRLF，并增加 Python 查找顺序。它先尝试 `py -3`，再尝试 `python` 和 `python3`。三者都不存在时，用中文说明需要安装 Python 3.10 或更高版本。

## 无 SSH 模式依赖修复

旧实现虽然不执行 SSH，却在导入部署模块时立即导入 Paramiko，导致只测速的用户也必须安装第三方依赖。完备性检查把 Paramiko 改为部署时按需加载。

使用 `python -S` 禁用第三方站点包后，`interactive_vps_pair` 仍能成功导入，且 `sys.modules` 中没有 Paramiko。日常动作 `1`、`2`、`6` 因此只依赖 Python 标准库。

## 2026-08-31 历史实测

最终从 Windows PowerShell 5.1 启动包装脚本，选择动作 `2`。连接已授权固定端 A 和测试端 B，复用本地令牌。实机地址、端口和身份信息只保存在本地私密记录，不作为开源默认配置。

参数为下载 64 MB、上传 32 MB、延迟采样 5 次、单项超时 45 秒。脚本没有询问 SSH 信息或密码。

健康检查覆盖两端原版首页、双 VPS 页面和代理健康接口，六个页面或接口都返回 HTTP `200`，代理版本均为 `1.2.0`。脚本同时发现固定端时钟落后本地约 252.8 秒，测试端落后约 188.2 秒，并把警告写入报告。

双向结果为：固定端到测试端下载 36.71 Mbps、上传 32.96 Mbps、平均 HTTP 延迟 3.241 ms、抖动 0.108 ms、请求失败率 0%；测试端到固定端下载 30.61 Mbps、上传 39.45 Mbps、平均延迟 3.195 ms、抖动 0.186 ms、请求失败率 0%。

脚本退出码为 `0`，生成 `interactive_report_20260831-060752.md` 和同名 JSON 报告。两份文件留在本地 `new/reports`，不进入公开仓库。

## 2026-09-06 本轮实际复验

先核对了工作区和既有服务状态，再把新版部署到原有两台授权节点的独立增强端口。部署复用现有令牌及系统已知 SSH 身份，不修改官方原版服务、不改云防火墙或系统时间。镜像构建期间旧容器继续运行，候选健康通过后完成切换。

随后从 Windows PowerShell 5.1 的包装入口运行动作 2，逐项提供两端地址、HTTP 协议、原 Web 端口，选择复用令牌、保存节点配置，并明确确认执行。参数为下载 64 MiB、上传 32 MiB、延迟 5 次、超时 45 秒；本轮预算是 192 MiB。

六个页面或代理健康检查均返回 200，两端代理版本为 1.3.0。固定端发起下载 36.32 Mbps、上传 33.79 Mbps；测试端发起下载 27.71 Mbps、上传 39.62 Mbps。两端延迟采样都成功 5 次，没有 HTTP 失败。脚本没有询问 SSH 密码，没有在这次日常测试中部署或重启服务，最后正常退出并生成自然语言报告。

本地证据是 `new/reports/interactive_report_20260906-065109-426283.md` 及同名 JSON。报告包含每次成功样本、耗时、实际字节和时间偏差，不仅是一张速度表。两端时钟分别比本地落后约 276.8 秒和 211.0 秒，只记录警告，没有擅自校时。这些实际报告与节点配置均被 Git 忽略。

## 更换测试端操作

以后更换测试 VPS 时选择动作 `4`。固定端保持原地址；测试端改成新机器；填写新机器自己的 SSH 参数；继续复用现有令牌。脚本只构建和切换测试端，固定端不中断，随后自动执行完整验收。
