# 高可用保障清单

## 先明确“高可用”的范围

本项目中的高可用，指单节点服务具备自动重启、可重复部署、部署前保留旧服务、失败后有回滚路径、结果可验证、错误可追溯。它不代表双机热备、跨区域容灾或 99.99% 服务等级承诺。

固定端或测试端的宿主机宕机、网络被运营商阻断、Docker 服务损坏时，对应方向一定不可用。要解决宿主机级故障，需要另行增加备用节点、负载均衡、监控告警和数据面切换，这不属于当前两 VPS 一键互测范围。

## 已经实现并验证的措施

### 容器自动恢复

两端容器都使用 `--restart unless-stopped`。只要 Docker 守护进程正常，容器异常退出会被重新拉起，服务器正常重启后也具备自动启动配置。

本轮通过远端容器启动参数确认了策略存在，但没有为了测试而重启两台 VPS。因此“主机重启后恢复”属于配置已确认、整机重启未实测。

### 可重复构建

实际部署 Dockerfile 不再使用会随时间变化的 `ghcr.io/librespeed/speedtest:latest`，而是固定为内容摘要：

`sha256:c2d5da9b11ffaf6fab535e4b84405878e67a714d650d292319369278834eb1c8`

固定摘要能保证同一源码在两台机器上拉到同一官方基础镜像。代价是上游安全更新不会自动进入项目，维护者需要定期主动检查上游并经过测试后更新摘要。

### 候选镜像切换

部署脚本先构建 `librespeed-vps:next`。构建阶段旧的 `librespeed-vps` 容器继续工作，只有候选镜像构建成功后才进入端口切换。

切换前，脚本把当前容器镜像保留为 `librespeed-vps:rollback`，同时将原容器改名为 `librespeed-vps-previous` 后停止。新容器启动后，最多检查 45 次，每次 HTTP 最多 3 秒并间隔 2 秒，因此等待可接近 225 秒，而不是固定 90 秒；Docker 命令自身阻塞时间另计。检查使用容器自己的端口和令牌，通过后才把候选镜像标记为当前版本。

如果候选启动或健康检查失败，EXIT 清理路径删除失败候选，把旧容器改回原名并启动。恢复的是原有端口、环境变量、令牌、挂载和容器设置，不是拿新配置启动旧镜像。恢复成功后本次部署仍以失败退出，让调用者知道新版本没有上线。发现上次残留的 previous 容器时拒绝继续覆盖现场。成功切换会删除 previous 容器，因此旧配置保留只覆盖本次失败恢复窗口，并非无限历史备份。

2026-09-06 两端实机升级验证了成功路径。新增四项测试用真实 Bash 执行部署脚本，用有状态的 Docker 替身验证构建失败、候选启动失败、健康失败和成功切换；比较了原端口、令牌和挂载。它们是状态机故障模拟，不是生产 Docker、断电或 kill -9 故障演练，不能混称为实机破坏性演练。部署文件锁还阻止同一节点并行升级，但本轮 Shell 替身测试不验证内核 flock 实现。

### 单任务锁

`pair.php` 和 `measure.php` 在每个节点上使用非阻塞文件锁。同一节点已有测速运行时，新请求立即返回 HTTP `409`，不会叠加下载、上传临时文件和网络流量。

真实并发测试中，第一个双向测试返回 `ok`，同时发起的第二个请求返回 `409`，该保护已经实测。

### 严格成功判定

1.3.0 的下载、上传和延迟请求要求命令成功、目标 HTTP `2xx`，不接受跳转。下载字节数、上传发出字节数必须和参数一致，上传响应和延迟响应必须为空。HTTP 200 的错误页面也会失败。任何一个指标失败，单向及双向结果相应标记为 `error`；部分延迟样本失败但仍有成功样本时可形成统计，须同时阅读失败率。

本轮故意把目标指向不存在路径，下载、上传、延迟三项全部被识别为失败，没有把 404 错误页当作高速下载数据。

### 重试和超时

只读健康 GET 遇到连接失败、502、503、504 时最多尝试三次。POST 双向测速只发一次，因为超时后远端可能仍在执行，重复请求会再消耗流量。401 和 409 也不自动重试。下载、上传有单项超时，延迟单次最多三秒，本地总超时按两方向及采样预算计算。

### 固定端不动、测试端可换

交互动作 `4` 只部署测试端。固定端不会被重新构建。每次测试时本地脚本把新测试端地址放进请求，因此固定端不需要为每一台新测试机修改静态配置。

固定端和测试端可以使用不同 SSH 端口、用户和密码，解决以后测试 VPS 配置不同的问题。

## 观测和审计

一次完整运行留下三类证据：

- 本地 Markdown 报告，用中文解释动作、健康状态、指标和失败原因。
- 本地 JSON 报告，保留每个 HTTP 状态、耗时、原始代理结果和摘要。
- 远端 `/opt/librespeed-vps/deploy.log`，保留构建、切换、健康和回滚过程。

交互脚本退出码为 `0` 才代表所选检查全部通过。退出码 `3` 表示流程完成且报告已保存，但至少一个健康检查或测速指标失败。

## 安全保障和限制

所有代理接口要求 `X-LibreSpeed-Token`。令牌错误返回 `401`，令牌不再允许放在 URL 查询参数。SSH 密码只在进程内存中使用，令牌和真实报告都由 Git 忽略。

当前演示端口使用 HTTP，令牌请求头会明文经过网络。令牌只能防止不知道令牌的人直接调用，不能抵御链路窃听。长期公开使用应配置 HTTPS，并用云防火墙限制来源地址。

代理允许持有令牌的人要求节点访问给定 HTTP/HTTPS 地址，因此令牌属于高权限凭据。它不能放进 GitHub、截图、群聊或公开网页源码。

## 已确认但未修复的环境问题

历史检查中两端 NTP 未启用。2026-09-06 06:50 的健康接口复验显示固定端时间约落后本地 276.8 秒，测试端约落后 211.0 秒。本轮通过 HTTP 观测偏差，没有再次声称检查过全部授时服务配置。

本地脚本会把超过 30 秒的时钟偏差写成警告。由于直接跳变系统时间可能影响服务器上的其他服务，本轮只读确认后没有修改系统时钟。该问题不影响按各节点本机持续时间计算的 Mbps，但影响跨节点绝对时间戳排序。

这些内容是明确边界，不应在 README 或发布说明中被包装成已经完成。容器进程仍活着但内部卡死时，unless-stopped 不会主动修复；本项目没有常驻健康监控或自动故障转移。基础镜像仍固定旧摘要，本轮没有把依赖更新或漏洞扫描伪装成已完成。
