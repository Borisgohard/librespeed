# 公开发布整改与验收

## 为什么要整改

本轮处理三个公开交付问题：旧中文记录仍可识别实测服务器；历史发布说明与实际私有状态不一致；虚拟环境没有完整加入 Git 忽略规则。补查还发现旧提交作者邮箱需要保护。因此不能只改根 README，更不能先公开再补隐私检查。

目标是让新用户下载、解压后能启动中文向导，按自己的服务器信息使用；同时公开仓库只提供软件、匿名技术说明与可复验测试，不提供私人服务器、账号或原始审计材料。

## 已实现的整改

历史 Markdown 去掉实际服务器地址、端口、个人工作区路径和旧提交定位，保留每次操作原因、故障现象、修复方法、参数与结果。虚构示例仅使用文档保留地址段，并明确不能直接连接。上游署名、许可证、源码、数据库和品牌资源没有为脱敏而删除。

忽略规则新增 `.venv/`、`venv/`、`.private/`、`*.bundle`。原始跟踪文件以 ZIP 备份，完整 Git 历史以 bundle 备份并验证；备份只放本地私密目录，不属于源码发行包。真实节点配置、令牌、SSH 身份记录和报告保持原位，没有重置，已有用户不需要重新部署。

统一入口是 Windows 的 `start.cmd`、Linux/macOS 的 `bash start.sh`，共同调用 `start.py`。它检查 Python 3.10 最低版本，优先复用项目 `.venv`，再进入原来的六动作向导。没有 Git 或配置也能启动，但用户仍须安装 Python、拥有两台 VPS 并放行端口。

仅在选择部署且缺少 Paramiko 时，才询问是否准备依赖。明确同意后创建项目内虚拟环境、安装固定版本要求并验证导入，然后重新打开向导。取消、输入中断或安装失败不会连接 VPS；安装本地依赖不等于同意后续远程部署。已有不完整虚拟环境不会被覆盖。

官方单机脚本的公开默认 Web 端口改为通用的 `8080`，仍可用 `PORT` 覆盖。该文件修改不会改变已有容器端口。本轮不重部署服务器，不触碰独立官方服务，也不重复消耗 VPS 测速流量。

## 测试与发布状态

本地最终运行 60 项自动检查，48 项通过、12 项明确跳过：11 项需要本机没有的 PHP，另 1 项是仅在 Linux 验证的 Shell 启动入口。新增 Windows 包装入口实测通过，包括中文、带空格目录、从其他工作目录启动和输入结束时安全取消。

源码候选提交已在现有私有仓库的 `codex/public-ready` 分支验收。GitHub 五个作业全部成功：Windows 新手启动、Python 3.10、Python 3.14、桌面和手机网页交互、Shell/PHP/真实镜像构建。逐步骤确认了 Windows 与两种 Python 的真实依赖安装，而不是只用模拟安装结果；PHP 运行和 Linux Shell 入口也由对应作业实际覆盖。

本地从不含配置、Git 目录或第三方依赖的发行副本启动，选择部署并明确同意准备环境后，真实安装并导入 Paramiko 5.0.0，重新进入向导后取消。没有生成令牌或节点配置，没有连接 VPS。另一次真实 GitHub ZIP 下载验证使用只测速相关动作，并以 `-S` 禁用站点包，仍能进入日常流程并安全退出。

待发布文件共 158 个，远端 Git 文件树与本地逐项比较了路径、内容摘要和文件模式，完全一致。下载 ZIP 初次直接比较发现两个 Windows 入口摘要不同；进一步确认仅是 `.gitattributes` 声明的 LF/CRLF 转换，规范化这两项后全部摘要一致，没有忽略其他内容差异。

候选版本从无父提交的新历史开始，作者和提交者均使用 GitHub noreply 邮箱。扫描全部候选文件及该历史，没有命中本地已知节点地址、实际端口、密码、令牌及其指纹、个人邮箱或工作区路径。扫描曾把上游 SVG 的小数坐标误报为端口，核实后限定数字边界，并未修改上游 Logo 或放宽真实地址检查。

在同一有权限的 GitHub API 下，候选 README 为 200，令牌、节点配置、SSH 身份记录、虚拟环境和历史备份路径为 404；完整文件树也排除了真实报告。这证明候选内容边界，不是最终匿名公开验收。

**历史隔离已执行，正在验收新仓库。** 仓库所有者明确同意后，旧仓库已改名并保持私有归档，在原项目地址创建了独立、非分叉的新仓库。新仓库先保持私有，只接收干净候选历史，没有导入旧分支、标签或工作流记录。本地主分支同步到与原工作区内容相同的干净候选，真实配置、令牌和报告没有覆盖。新仓库还需完成主分支 CI、匿名读取代码和下载 ZIP，并验证旧提交与私密路径无法访问；验收完成前不把候选通过写成已经公开。

本轮尝试清理两个仅供测试的解压副本和其中的虚拟环境，命令在执行前被环境策略拦截。没有更换工具绕过，也没有误删原始备份；副本暂留被 Git 忽略的 `.private/`，不在仓库或 VPS 部署包里。尚未验证 macOS 实机、离线安装或所有 Linux 发行版，本轮也未重复线上压测。

## 历史隔离原则

旧提交即使从分支上移除，也可能通过 GitHub 旧链接或工作流入口被访问。完整旧记录留在私密备份，干净公开历史使用 GitHub noreply 邮箱，不重新上传旧对象。本轮经明确确认采用“保留私有旧仓库、原地址建立独立新仓库”，新仓库内部编号与旧库不同，工作流重新运行，项目对外地址不变。

已经被第三方克隆、截图或缓存的历史内容无法由本项目保证撤回。此次检查的保证范围是新发行文件、可达提交与实际核验的 GitHub 公共入口，不声称抹除互联网上所有历史副本。

## 记录分别放在哪里

- 实现思路：`new/交互脚本实现思路.md`，解释交互与隐私边界。
- 编写过程：`docs/编码过程详解.md`，解释新增文件和修改依据。
- 操作审计：`docs/操作审计手册.md`，记录实际检查、测试、失败和发布结果。
- 原始私密证据：本地 `.private/` 及 `new/reports/`，不进入公开仓库。
