# 仓库文件总览

## 阅读方式

这份清单解释仓库里的所有要素属于哪一层、是否参与实际部署，以及为什么要保留。它以 `git ls-files` 为公开文件边界；本地令牌和真实运行报告单独列在“只存在本地的文件”中。

旧基线共有 152 个文件。本次公开整改增加三个根目录启动文件、一个本地环境准备模块、一份启动测试和一份公开验收说明，共 158 个。具体提交以 `git ls-files` 为准；下文按层说明全部要素，不把私密运行文件算入公开交付物。

最重要的区别是：`new/project` 保存了较完整的 LibreSpeed 上游源码快照，方便保留原版功能和追溯来源；真正通过 SSH 发往 VPS 的不是整个目录，而是九个运行文件组成的最小部署包。

## 根目录

- `.gitattributes`：规定通用文本和 Linux 脚本使用 LF，PowerShell 脚本使用 CRLF，图片、字体、数据库和 PHAR 按二进制处理。
- `.gitignore`：排除令牌、环境变量文件、私钥、Python 缓存、日志、临时压缩包和真实运行报告。
- `LICENSE`：项目根级 LGPL-3.0-or-later 许可证副本。
- `README.md`：面向第一次接触项目的用户，解释用途、选择路径、每个输入、报告、高可用和故障处理。
- `start.cmd`：Windows 双击入口，结束时保留窗口。
- `start.sh`：Linux/macOS 入口，用 `bash start.sh` 运行，不依赖解压后的可执行权限。
- `start.py`：校验 Python 版本、优先使用本项目 `.venv`，启动原有中文向导。
- `.github/workflows/quality.yml`：本仓库真正生效的 GitHub Actions，执行 Python、Shell、PHP 和 Docker 构建检查。
- `tests/test_local_scripts.py`：测试部署包、参数范围、超时、结果判定、时钟警告和报告脱敏。
- `tests/test_repository_integrity.py`：测试关键文件、敏感文件边界、换行、README 链接和固定镜像摘要。
- `tests/test_startup.py`：测试全新解压式启动、依赖安装同意/取消/失败、项目虚拟环境和日常测速免 SSH 依赖。
- `tests/test_review_regressions.py`：输入结束、取消整条向导、HTTP 跳转/重试、畸形数据、配置保存、令牌备份、流量预算和打包异常回归。
- `tests/test_deployment_transaction.py`：用真实 Bash 验证构建失败、启动失败、健康失败及成功切换的原配置保留。
- `tests/support/docker_simulator.py`：上项测试使用的有状态 Docker 替身，只改隔离目录中的测试状态，不控制真实 Docker。
- `tests/test_agent_runtime.py`：本机 HTTP 测试后端与真实 PHP/curl 配合，验证状态、字节、空响应、跳转及脱敏。
- `tests/support/php_container.sh`：在隔离容器里调用 PHP 的小入口，供远端测试使用。
- `tests/run_remote_checks.py`：在已授权测试机创建唯一临时容器、上传 PHP 测试、运行并清理，不替换正式容器。
- `tests/browser_smoke.cjs`：使用模拟请求验证桌面和手机网页的表单、流量确认、复制、导出、错误转义及布局。

## 远端产生但不属于仓库的文件

- `/opt/librespeed/deploy.log`：官方原版部署日志。
- `/opt/librespeed/docker-compose.yml`：官方原版部署生成的 Compose 文件。

- `/opt/librespeed-vps/src-随机标识.tar.gz`、`build.随机标识/`：1.3.0 的本次源包和构建目录，成功或正常失败后都会清理。旧版 `src.tar.gz`、`src/` 若仍存在属于历史产物，不会盲目递归清理。
- Docker 容器 `librespeed`：官方原版服务。
- Docker 容器 `librespeed-vps`：魔改双 VPS 服务。
- Docker 容器 `librespeed-vps-previous`：升级期间临时保留的原容器；正常结束后不存在，异常恢复未完成时保留现场。

远端日志和镜像不上传 GitHub。需要排错时由部署脚本或 SSH 在服务器本机查看。
