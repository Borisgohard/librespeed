# 实现思路留存

官方单机部署脚本的目标，是在一台 VPS 上稳定部署原版 LibreSpeed，并尽量减少远端系统差异带来的失败概率。LibreSpeed 本身依赖 Web 服务器和 PHP，官方 Docker 镜像已经把这些环境封装好，所以最稳妥的方式是复用官方镜像，而不是在远端手工安装和配置 Apache、PHP 以及扩展。

脚本把远端安装目录固定为 `/opt/librespeed`。这个目录只保存部署编排文件和部署日志，不承载业务数据。容器名称固定为 `librespeed`，这样后续查看日志、重启或替换容器时都有稳定名称。公开脚本的宿主机默认端口是通用的 `8080`，容器内也使用 `8080`，二者通过 Docker 端口映射连接；已有服务占用时通过 `PORT` 另选空闲端口。

脚本执行时先确认当前用户是 root，因为安装 Docker、启用系统服务和绑定端口都需要管理员权限。随后脚本会检查 Docker 是否存在。如果 Docker 已经安装，就直接复用；如果没有安装，就根据系统包管理器执行安装。安装和拉取镜像都带有重试逻辑，避免偶发网络抖动直接导致失败。

最初脚本假设 Docker Compose 插件可用，但实际在 Debian 13 上发现该包不存在。最终设计改为：如果 Compose 可用，就写入并使用 Compose 文件；如果不可用，就使用 `docker run` 直接启动容器。这样既保留了结构化配置，也不会因为 Compose 包名差异阻断部署。

脚本的验证标准是明确的。容器启动后，必须能在远端本机访问所配置的端口，默认是 `http://127.0.0.1:8080/`。如果访问失败，脚本会打印容器最近日志并退出。只有健康检查通过后，脚本才会输出访问地址和后续维护提示。

对于网络问题，脚本不默认开启代理，因为代理不是所有环境都需要。只有依赖安装、镜像拉取或网络访问多次超时时才考虑代理。脚本运行在 VPS 时，VPS 的 `127.0.0.1` 不是用户电脑；只有代理本身位于 VPS，或用户已经建立安全隧道时，才能填写 `127.0.0.1:42343`。

当前脚本用官方内容摘要代替 `latest` 作为默认镜像。这样做让部署结果可重复，但不会自动获得上游更新。维护者应把更新摘要视为一次明确发布：先确认上游变化，运行测试，再更新默认值和审计记录。
