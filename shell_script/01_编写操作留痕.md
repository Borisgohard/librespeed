# 编写操作留痕

本文件记录官方 LibreSpeed 单机部署脚本的本地编写过程。工作开始时，项目文件夹是空目录，也不是 Git 仓库。为了让后续交付内容有明确边界，我在根目录下新建了 `shell_script` 文件夹，把官方部署脚本和相关记录都放在这个文件夹中。本公开副本隐去工作区绝对路径，原始记录仅保存在本地私密备份。

我先从 GitHub 学习了 `librespeed/speedtest` 项目，并在本地临时浅克隆了上游源码。用于学习的上游提交是 `a293ac4cb92031d7b21a5dcde9cdbd62964e9900`，提交摘要显示它是 2026 年 6 月 15 日合并的 Alpine 镜像依赖更新。这个临时克隆只用于阅读和确认实现方式，最终已经从工作区删除，没有作为交付物保留。

阅读上游源码后，我确认 LibreSpeed 的标准运行方式是 Web 服务器加 PHP。官方 Docker 镜像已经封装了 Apache、PHP、前端页面、后端测速接口和入口脚本。因此，我没有手工拼 Apache 配置，而是编写了 `shell_script/deploy_librespeed.sh`，让它基于官方镜像完成部署。

公开脚本默认把 LibreSpeed 部署到宿主机 `8080` 端口，容器内继续使用官方默认的 `8080` 端口。历史实测用过的私人端口不作为开源默认值。脚本会创建远端目录 `/opt/librespeed`，把部署日志写入 `/opt/librespeed/deploy.log`，并把容器命名为 `librespeed`。标题、端口、镜像名、容器名和安装目录都可以通过环境变量覆盖。

脚本还加入了健康检查。容器启动后，它会访问本机配置的 Web 端口；使用默认值时就是 `http://127.0.0.1:8080/`，确认 Apache 已经返回正常页面。如果健康检查失败，脚本会输出最近的容器日志，方便判断是镜像、端口还是服务启动问题。

根据项目执行要求，如果安装依赖或拉取镜像时遇到持续网络超时，可以临时使用代理。完备性检查纠正了旧提示：部署脚本运行在 VPS 时，`127.0.0.1` 指的是 VPS 自己，不是用户的 Windows 电脑。只有代理和脚本在同一机器，或已经建立安全隧道时，VPS 才能使用 `127.0.0.1:42343`。

最初脚本默认拉取 `latest`。为了避免未来相同脚本部署出不同版本，当前默认镜像已经固定为 `2026-08-31` 解析到的官方内容摘要。用户仍可以通过 `IMAGE` 环境变量明确覆盖，但升级应先测试再执行。
