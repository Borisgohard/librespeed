# LibreSpeed 双 VPS 测速工具

[![完备性检查](https://github.com/Borisgohard/librespeed/actions/workflows/quality.yml/badge.svg)](https://github.com/Borisgohard/librespeed/actions/workflows/quality.yml)

**坐在自己的电脑前，测试两台远程服务器之间的网速，并拿到中文报告。**

例如，你有一台长期使用的服务器 A，正在比较新买的服务器 B 和 C。先让 A 与 B 互相下载、上传，再把测试端换成 C；你的电脑只负责发指令和收报告，测速数据直接在服务器之间传输。整个流程由中文向导逐步询问，不需要你手工登录服务器敲部署命令。

这是基于 [LibreSpeed](https://github.com/librespeed/speedtest) 的增强项目。原有“浏览器到服务器”的测速页面仍保留，新增的是“服务器到服务器”的双向测速与本地自动部署。

```text
原有功能：你的浏览器 <----测速数据----> 一台服务器

新增功能：固定端 A   <----测速数据----> 测试端 B（以后可以换成 C）
            ^                           ^
            +----你的电脑：发指令、收结果----+
```

本文的 `192.0.2.10` 和 `198.51.100.20` **只是虚构示例地址，不能直接使用**。仓库不提供公共测速账号、令牌或免费测试服务器，请填你自己有管理权限的两台 VPS。

## 一分钟选对入口

| 你现在要做什么 | 向导里选什么 | 是否需要 SSH 密码 |
| --- | --- | --- |
| 两台服务器第一次安装，或一起升级 | `3`：部署两端、检查、测速 | 两台都需要 |
| 已安装好了，今天只想看网速 | `2`：检查、测速 | 不需要 |
| 换了一台新的测试服务器，固定端不动 | `4`：只部署测试端、检查、测速 | 只需要新测试端 |
| 只想知道服务是否在线，不消耗大笔测试流量 | `1`：只检查 | 不需要 |
| 只更新固定端 | `5`：只部署固定端、检查、测速 | 只需要固定端 |
| 已确认服务正常，直接测速 | `6`：只测速 | 不需要 |

**第一次用选 `3`，以后通常选 `2`，更换测试服务器选 `4`。** 即使选 `2`，各步骤仍会等你确认，不会打开脚本就自动跑流量。

## 开始前准备

| 准备项 | 具体要求 |
| --- | --- |
| 本地电脑 | Windows、Linux 或 macOS，Python 3.10 或更高版本；Windows 有专门入口 |
| 两台 VPS | 推荐 Debian/Ubuntu，使用 systemd；自动部署需可直接以 root 密码登录 SSH，不会自动提权 |
| 服务器信息 | 各自的公网 IP/域名、SSH 端口、root 密码、准备使用的 Web 端口 |
| 网络 | 本地能连接需要部署的节点 SSH；本地和另一台 VPS 都能连接各节点的 Web 端口 |
| 云防火墙 | 在云控制台安全组和主机防火墙中放行对应 TCP 端口；脚本不会替你修改防火墙 |
| 下载依赖 | 初次部署需要服务器访问系统软件源和 GitHub 容器镜像仓库；已有 Docker 时直接复用 |

SSH 端口用于安装程序，Web 端口用于访问网页和测速，**两者不是同一个端口**。例如 SSH 用 `22`，Web 用 `8080`。两台不同服务器可以都用 `8080`；已有业务占用时，换一个空闲端口。

部署会使用 `/opt/librespeed-vps` 和名为 `librespeed-vps` 的 Docker 容器。请不要把无关业务放在这个容器名或目录下；已有同名容器会被当作本项目旧版本替换。Docker 安装、镜像和临时上传文件会占用磁盘，不建议在磁盘快满时操作。

## 第一次部署：跟着做

### 第 1 步：下载到自己的电脑

在本页右上方点 **Code → Download ZIP**，解压后进入包含本 README 的文件夹。不要在压缩包里直接运行文件。

会使用 Git 也可以：

```powershell
git clone https://github.com/Borisgohard/librespeed.git
cd librespeed
```

后续命令都在这个项目文件夹里执行。Windows 可以在文件夹地址栏输入 `powershell` 再按回车，打开位置正确的终端。

### 第 2 步：安装 Python（已有就跳过安装）

Windows 安装 [Python](https://www.python.org/downloads/) 时启用命令行启动器，然后执行：

```powershell
py -3 --version
```

应该显示 Python 3.10 或更新版本。若你的电脑没有 `py`、只有 `python`，改用 `python --version`。本项目不捆绑 Python，也不会静默替你安装系统软件。

**不用提前手动安装 Paramiko。** 选择首次部署时，如果当前环境缺少它，向导会先问是否在项目内的 `.venv` 安装。你输入 `y` 才联网下载；完成后会重新打开向导，请再次选择动作。只选 `1`、`2` 或 `6` 不安装第三方依赖。

Linux/macOS 先确认：

```bash
python3 --version
```

Debian/Ubuntu 如果在准备环境时提示没有 `venv`，用系统包管理器安装 `python3-venv` 后重试。日常 HTTP 测速不需要虚拟环境。

### 第 3 步：启动中文向导

Windows：**双击根目录 `start.cmd`**。运行结束窗口会停留，便于查看结果或错误，不要双击内部 `.py` 文件。使用终端也可以：

```powershell
.\start.cmd
```

Linux/macOS：

```bash
bash start.sh
```

电脑装了多个 Python 时，也可明确执行 `py -3 start.py` 或 `python3 start.py`。Windows 入口依次寻找 `py`、`python`、`python3`；统一入口优先复用项目根的 `.venv`，不需要手工激活。已有不完整的 `.venv` 会停下并提示先移走备份，不会覆盖你的文件。

原有 `new/interactive_vps_pair.ps1` 和 `.py` 入口保留。解压版运行不需要 Git；首次部署仍需你提供两台 VPS 的管理权限、放行端口和允许环境下载依赖。“开箱即用”不意味着提供免费服务器或绕过这些条件。

### 第 4 步：按提示输入

下面的示例表示“用自己的 A 和 B 第一次部署”。IP 必须替换为你的真实地址，不能照抄示例。

| 提示 | 怎么填 | 为什么 |
| --- | --- | --- |
| 执行动作 | `3` | 第一次要把两端都装好 |
| 固定端 IP/域名 | A 的地址，例如 `192.0.2.10` | 不要带 `http://` 或端口 |
| 固定端 Web 端口 | 例如 `8080` | 浏览器访问和测速使用 |
| 固定端 Web 协议 | 回车选 `http` | 自动部署提供 HTTP 服务 |
| 测试端 IP/域名、端口、协议 | B 的地址，例如 `198.51.100.20`、`8080`、`http` | 两个地址必须代表不同 VPS |
| 两端 SSH 端口、用户名 | 按云控制台填写，例如 `22`、`root` | 两台可以不同 |
| 代理访问令牌 | 首次部署直接回车生成 | 两端接口共同使用的钥匙，不是 SSH 密码 |
| 下载、上传大小 | 先用 `64`、`32` | 单位 MiB，下面解释实际流量 |
| 延迟采样、单项超时 | 先用 `10`、`60` | 分别是请求次数和秒数 |
| SSH 密码 | 输入各自的密码 | 输入时不显示字符是正常现象 |
| 是否保存节点配置 | 通常回车表示保存 | 下次不用重输地址，不保存密码 |
| 确认开始执行 | 核对后输入 `y` | **直接回车是取消**，不是执行 |

每个阶段出现“按 Enter 继续”时，按回车进入下一步。输入意外结束或按 `Ctrl+C` 会停止流程，不会把缺失输入当成同意。

首次连接陌生服务器时，会显示 `SHA256:...` SSH 身份指纹。用云控制台提供的指纹核对；也可以在可信云控制台终端用 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 查看对应密钥指纹。确认一致后输入完整的 `yes`。以后密钥变化会拒绝连接，不能不核对就删记录绕过提示。

### 第 5 步：等待部署、检查和测速

脚本依次上传少量项目文件、构建镜像、切换服务、检查网页、执行双向测速，最后显示两份本地报告路径。

当最后显示“报告已保存”，且没有失败提示，打开 `new/reports` 中刚生成的 `.md` 文件查看中文解释。`.json` 文件保留完整结构化数据，供排错和二次分析。测速慢或接口超时也会保存失败报告；不要只看有没有生成文件，要看“执行结论”。

## 日常测速与更换测试机

**日常测速：** 再运行同一个脚本，选 `2`。复用保存的节点信息和令牌，确认流量，再输入 `y`。整个过程不询问 SSH 密码，也不重启容器。只读健康检查失败时会跳过测速，避免无效耗流量。

**更换测试机：** 选 `4`，固定端保持原值，把测试端改成新机器的 IP、Web 端口和 SSH 信息，继续复用原来的令牌。脚本只部署新测试端，固定端不会重建。新地址随每次测速请求传入，所以固定端不需要预先登记所有测试机。

**旧测试机不会被自动删除。** 它的服务仍在运行；不再使用时请在云控制台停止该容器或关闭对应端口。不要为了替换 B，误删固定端 A。

**升级现有安装：** 更新本地项目后选 `3`，填现有端口并复用现有令牌。1.3.0 不再内置作者的服务器地址，旧用户需要输入一次自己的节点信息并选择保存。请先备份本地私密文件，不要用 ZIP 覆盖它们。

## 流量与结果，怎样才不会看反

`MiB` 是数据量单位，1 MiB = 1,048,576 字节。`Mbps` 是速度单位，数值除以 8 约为十进制 MB/s。例如 80 Mbps 约为 10 MB/s，不是每秒 80 MB。

默认下载 64 MiB、上传 32 MiB，一轮会执行四次文件传输：

| 报告里的项目 | 实际数据走向 | 数据量 |
| --- | --- | ---: |
| 固定端发起的下载 | B 把数据发给 A | 64 MiB |
| 固定端发起的上传 | A 把数据发给 B | 32 MiB |
| 测试端发起的下载 | A 把数据发给 B | 64 MiB |
| 测试端发起的上传 | B 把数据发给 A | 32 MiB |

合计有效载荷约 **192 MiB**，每台 VPS 各发送约 96 MiB、接收约 96 MiB。协议开销另计，收费规则以服务商为准；重复三轮，流量也约变成三倍。向导在执行前会显示预算，但它不是云账单硬上限。

报告还解释每项实际字节数、耗时、HTTP 状态、最小/平均/最大延迟、抖动、成功/失败采样数和每个成功样本。部分失败时，其他成功指标仍保留。用时不足一秒会提示样本太短，不把突发速度包装成稳定带宽。

这里的“延迟”是 HTTP 请求往返时间，包含连接和服务响应开销；“抖动”是相邻成功延迟样本的差值绝对值平均；“请求失败率”是这些 HTTP 请求失败的比例，**不是 ICMP 丢包率**。有少量样本失败时仍可能得到延迟统计，应同时看失败率，而不只看总状态。

例如一次报告显示 A 发起下载 80 Mbps、上传 40 Mbps，只能说明当时 B→A 的下载吞吐比 A→B 的上传吞吐高；不能单凭一次结果断言某台 VPS 的标称带宽虚假。建议在同样参数下重复测量，比较时段与方向，不盲目追求最大测试流量。

## 原版功能是否保留

每台部署好的节点都有两个入口，以下仍是示例：

- `http://192.0.2.10:8080/`：原版浏览器测速。数据经过打开网页的设备，测的是设备到该 VPS。
- `http://192.0.2.10:8080/vps.html`：服务器间测速。填写同一个代理令牌和 B 的完整地址即可运行，可复制或下载 JSON 报告。

原版下载、上传、延迟、抖动、IP 信息、现代/经典页面、稳定性页面及相关源码均保留。上游多服务器模式、遥测、结果数据库属于**需要额外配置的可选能力**，一键脚本默认独立模式、遥测关闭，不会自动配置数据库。

新增代理复用原版 HTTP 后端，但使用服务器上的单连接 `curl` 传输；它不是把浏览器 Worker 的多连接、自适应时长算法原封不动搬到服务器上。因此两套结果不要求数值相同，也不替代 `iperf3`、路由追踪或专业长期监测。

## 本地文件与安全

| 文件 | 用途 | 会上传 GitHub 吗 |
| --- | --- | --- |
| `new/.vps_pair.json` | 你选择保存的两端地址、端口、协议、SSH 用户名 | 不会 |
| `new/.vps_token` | 当前代理令牌 | 不会 |
| `new/.vps_token.previous` | 更换令牌时保存的上一份，只有一代 | 不会 |
| `new/.ssh_known_hosts` | 你明确确认的 SSH 服务器身份 | 不会 |
| `new/reports/` 中的实测报告和截图 | 本次实际地址、时间、参数、结果和错误 | 不会，只有目录说明公开 |
| `.venv/`、`venv/` | 本地 Python 与部署依赖 | 不会 |
| `.private/`、`*.bundle` | 本地原始私密审计、旧历史和发布备份 | 不会 |

令牌只在确认执行后、至少一个节点部署或认证健康检查成功后保存；测速成功也可确认保存。取消不会覆盖旧令牌。两端必须使用同一个令牌；单端部署不允许凭空生成新令牌。丢失后应同时重新部署两端来统一令牌，不要把旧端和新端分别设置不同的值。

SSH 密码只在本地进程内使用，不写报告。令牌会存在服务器容器配置中，服务器 root/Docker 管理员能够读取它。`.gitignore` 只能防止 Git 误传，不能加密硬盘；Windows 用户还应控制项目文件夹访问权限，公开截图前也要检查敏感内容。

**HTTP 不加密令牌。** 长期使用应限制 Web 端口来源为本地出口 IP 和对端 VPS，或由有经验的管理员配置 HTTPS。已有 HTTPS 时向导支持选 `https`，但两端证书须可信，且容器的 `LIBRESPEED_PUBLIC_URL` 必须和实际外部地址一致；本脚本不签发证书、不修改反向代理，也不跟随跳转传送令牌。

令牌允许持有人要求服务器访问指定 HTTP/HTTPS 地址，属于高权限凭据，不应分享给陌生人。保留的原版网页和下载接口没有新增令牌门槛，因此即使不知道代理令牌也可能消耗网页测速流量，防火墙限制仍然重要。

## 常见问题

| 现象 | 怎么排查 |
| --- | --- |
| 找不到 Python | 安装 Python 3.10 或以上；关闭旧终端后重新打开，执行 `py -3 --version` 或 `python3 --version` 确认 |
| 缺少 Paramiko | 用根目录启动器选部署，按提示同意准备项目 `.venv`；日常检查/测速不需要安装 |
| 环境准备失败 | 查看终端下载错误，检查网络、磁盘和 `python3-venv`；不完整的 `.venv` 先移走备份，完整环境可以重试。失败不会连接 VPS |
| 提示地址非法 | 地址栏只填 IP/域名，不带协议、端口、路径或空格；Web 端口单独填 |
| SSH 超时、认证失败 | 核对 SSH 端口、安全组、root 密码和是否允许密码登录；Web 端口开放不代表 SSH 已开放 |
| SSH 身份变化 | 先确认是否重装或更换机器，再核对新指纹；不要直接接受未知密钥 |
| 本地节点配置损坏 | 保留 `.vps_pair.json` 的副本，移到项目外后重新输入；不要删除令牌来解决地址配置问题 |
| HTTP 401 | 令牌不对或两端不一致，检查当前与上一份本地令牌；必要时选 `3` 统一重部署 |
| HTTP 409 | 节点正在测速，等现有任务结束；不要连续重复提交。部署冲突会单独在 SSH 输出中提示 |
| HTTP 400 / 地址不匹配 | 检查固定端 URL 是否和健康接口的 `publicUrl` 一致；域名、协议、端口变化后要同步服务器配置 |
| 首页正常、健康检查失败 | 页面能打开不代表代理配置正确；看版本、令牌和具体 HTTP 状态，不要只看 200 |
| 一边成功、一边失败 | 检查两台 VPS 之间是否互通，而不只是本地能访问；报告会保留成功子项 |
| 超时 | 可能仍有服务器任务执行，不会自动重复发起测速；等待后减小数据量或适当提高超时 |
| 镜像构建失败 | 原服务在构建阶段继续运行；检查远端 `/opt/librespeed-vps/deploy.log`、磁盘和软件源网络 |
| 升级后恢复失败 | 保留 `librespeed-vps-previous` 和日志，先检查容器状态；脚本拒绝覆盖未恢复现场 |
| 时间偏差警告 | 核对 VPS 与本地时钟；本工具只报警，不擅自修改系统时间 |

退出码：`0` 所选检查通过；`1` 取消或输入结束；`2` 执行异常；`3` 检查/测速未全部通过且报告已保存。取消发生在部署之后时，已完成的远端变更不会凭空撤销，失败报告会记录最后阶段。

## 可用性做到了哪一步

已经实现：固定基础镜像摘要、旧服务运行期间构建候选版本、单节点部署锁、候选失败恢复**原容器及原配置**、容器退出自动重启策略、测速单任务锁、严格检查 HTTP 状态与传输字节、有限只读重试、POST 测速不自动重试、中文失败报告。

这不是双机热备集群，没有宿主机故障自动切换或在线监控告警。切换端口时有短暂停机；容器进程卡住但不退出时，Docker 重启策略不会自动修复。断电、强制杀死部署进程、长时间压测、首次安装全部发行版及 ARM 平台不在本轮完整验收范围。详见 [高可用保障清单](docs/高可用保障清单.md)。

## 开发者复验

普通用户不需要运行这些命令。维护者修改后可先运行：

```powershell
python -B -m unittest discover -s tests -v
git diff --check
```
